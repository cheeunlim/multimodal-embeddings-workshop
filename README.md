# **Multimodal Search Workshop: Enterprise-Grade Retrieval**

This project demonstrates how to build a high-performance multimodal retrieval system using Gemini models and hybrid search (Dense + Sparse) on Google Cloud. It is designed as a hands-on workshop to handle complex datasets involving both images and long-form videos.

## **Workshop Overview & Architecture**

The goal of this workshop is to build a system that can search across a mixed pool of images (Flickr 8k) and video chunks (from 4 long-form videos) using natural language queries.

The workflow consists of three main phases:

### **Phase 1: Advanced Video Processing**
Long videos (40-60 mins) are difficult to search effectively as a single unit. We segment them into non-overlapping 10-second chunks using OpenCV. This allows for granular retrieval and precise timestamp seeking.

### **Phase 2: Hybrid Search Architecture**
We combine two powerful search methods to avoid "semantic drift" and capture both concepts and keywords:
*   **Dense Search**: Uses `gemini-embedding-2-preview` to generate high-dimensional vectors capturing the visual essence of images and video chunks.
*   **Sparse Search**: Uses the BM25 algorithm on text descriptions to capture exact keywords (like part numbers or specific names).
    *   For images, we use human-written captions from the Flickr 8k dataset.
    *   For video chunks, we use **Gemini 2.5 Flash** to generate short text descriptions.

### **Phase 3: Post-Search Optimization**
*   **Video Crowding**: We implement logic to prevent a single video from dominating the search results, ensuring a diverse range of source materials in the top hits.
*   **Reranking**: We provide the code structure for a second-pass high-precision sorting using the Vertex AI Ranking API.

## **Pre-computed Data Registry (`full_dataset_registry.pkl`)**

To make the workshop efficient, we use a pre-computed registry file. Instead of processing large videos and thousands of images every time you open the notebook (which takes hours), we pre-compute the descriptions and embeddings and save them in this file.

### **What's inside it?**
It contains a list of dictionaries. Each dictionary represents a searchable item (either an image or a 10-second video chunk) and contains:
*   `id`: A unique identifier (e.g., image filename or video name + chunk index).
*   `type`: `'image'` or `'video_chunk'`.
*   `path`: The location of the file (local path or GCS URI).
*   `description`: The text associated with the item for Sparse Search.
*   `dense_embedding`: The vector generated by Gemini Embedding 2 for Dense Search.

## **Data Preparation Script (`prepare_full_dataset.py`)**

This standalone script is used to generate the `full_dataset_registry.pkl` file by processing the full dataset in the background.

### **Inputs:**
1.  **Flickr 8k Dataset**: Images and `captions.txt` stored in `gs://ai-multimodal-data/Flickr 8k/`.
2.  **4 Long Videos**: MP4 files stored in `gs://ai-multimodal-data/`.

### **Outputs:**
1.  `full_dataset_registry.pkl`: Saved locally and automatically uploaded to `gs://ai-multimodal-data/` for sharing.

## **Workshop Practice Notebook (`multimodal_search_tutorial.ipynb`)**

This is the interactive notebook for the workshop participants.
*   It imports the `full_dataset_registry.pkl` file (downloading it from GCS if not found locally).
*   It builds the BM25 index and executes the hybrid search.
*   It includes a "Practice Mode" that can process a small subset of data locally if the full pre-computed file is not available.

> [!TIP]
> **Optimization Idea (Fallback Strategy)**: If generating the `.pkl` file continues to fail or takes too long, we can refactor the notebook's fallback logic to use a pre-defined subset folder (e.g., using chunks/images from the `originals` folder) instead of downloading and processing full videos in the notebook. This will keep the notebook lightweight and fast.

## **How to Use**

1.  **Open Notebook**: Open `multimodal_search_tutorial.ipynb`.
2.  **Set Project ID**: Update the `PROJECT_ID` in the initialization cell.
3.  **Run Cells**: Execute the cells to load the data and test the hybrid search with queries like `"child in pink dress"` or video-specific keywords.
